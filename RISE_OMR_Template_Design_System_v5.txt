RISE OMR — Template Design System v5

Architecture for a fully configurable, dashboard-driven OMR engine. RISE 2027 is the first exam config — not a fixed template.

What changed in this pass: Header rebuilt as a branded blue banner with an editable logo slot and school name "RK ENGLISH MEDIUM SCHOOL" · blue + orange brand palette applied to header, section bars and accents · Phone Number moved into its own aligned line · Paper Set A–D rebuilt as evenly spaced bubbles matching the answer-bubble size · the QR badge box is now removed from the visible wireframe entirely — titles re-centered across the full banner — while machine identification (template/version/sheet/set) still exists in the template schema, generated onto the real PDF at render time rather than hand-drawn in this mockup.

1. System Flow
Dashboard → Database → Exam Config → Section Config → Layout Engine (auto-reflow) → Template Config (JSON, versioned) → PDF Generator → Print → RICOH IM 2700 Scan → OMR Recognition Engine → Marking Engine (configurable rules) → Results
Hard rule: the OMR sheet only records answers (bubble grid + registration marks + QR). Marking logic lives entirely in the evaluation engine, never in the physical layout.

2. Marks ≠ Question Count
Section marks, question count, and marks-per-question are three independent numbers stored separately — none derived from another. Validation only checks Σ(question marks) == allocated_marks; it never infers question count from marks, and — since the last revision — marks don't print on the sheet at all, so there's nothing to misread.

3. Color System
Two-color brand palette, used deliberately so it never touches the scanner-critical areas:

Element | Color | Why
Header banner background | Blue #123E7C | Brand identity, top of sheet only
Header accents, "OMR ANSWER SHEET" label, section accent strip | Orange #E8720C | Visual hierarchy, warmth against the blue
Section header bar fill | Light blue tint #EAF1FB | Section separation, still >90% light so contrast stays scanner-safe
Answer bubbles, registration marks, question numbers | Pure black on white | These are what the scanner samples — color never applied here, by design

Both brand colors are stored as brand_colors.primary / brand_colors.accent in the template config, so a different school on the same platform gets its own palette without touching the layout engine.

5. Section Header Hierarchy
Header bar = light-blue tint fill, thin orange accent strip on the left edge, section name in bold navy — no marks shown anywhere on the sheet. allocated_marks still lives in config and drives validation + the marking engine, it just never prints.

6. Student Information Block
Field | Type | Notes
Student Name | handwritten, full width | required
Class | handwritten | required
Section | handwritten | required

Paper Set | OMR bubble (A/B/C/D), 4mm diameter — same size/spacing as answer bubbles | enable/disable/rename sets from dashboard

7. Header / Branding — Fully Editable
Everything in the blue banner is a template field, not hard-coded art:

Field | Editable from dashboard
Logo | Upload PNG/SVG → fills the logo slot at fixed position/size
School name | Free text — "RK ENGLISH MEDIUM SCHOOL" for RISE, anything for the next exam
Exam title / subtitle | Free text — "RISE 2027", "RK INTEGRATED SCHOLARSHIP EXAMINATION", "OMR ANSWER SHEET"
Brand colors | primary / accent hex — swap blue/orange for any school's colors
Extra header line | Optional subtitle slot (year, batch, centre) — on/off

8. Machine Identification — No Visible QR Box
The wireframe no longer draws any QR box on the sheet. What it was drawing before was a decorative placeholder anyway — a real QR is generated by the PDF renderer at export time from qr.encodes (template_id, version, exam_id, sheet_id, paper set), not hand-illustrated in a mockup. That still leaves a decision for the actual PDF: either place a real generated QR somewhere unobtrusive (small, in a margin/corner, outside the header banner) or drop machine-scanned identification altogether and rely on the registration number + manual sheet sorting. The schema keeps qr as an optional block either way — qr.enabled: false turns it off cleanly without touching layout logic.

9. Registration Marks — 4 Marks
Top-left, top-right, bottom-left, bottom-right — pure black 4×4mm squares, positioned outside the branded banner in the plain white margin so color never interferes with corner detection.

10. Coordinate & Layout Strategy
Page setup — resolve page size → usable area = page minus margins minus quiet zone.
Fixed blocks placed first: header banner (logo + branding), student info grid, registration number — fixed heights regardless of exam config.
Remaining area split into N columns (default 2 for ≤60Q, 3 for >100Q).
Sections flow column-major in configured order; splits at question boundaries only, never mid-row.
Per-section height = header_bar_height (8mm, name-only) + (question_count × row_height).
Reflow triggers: question_count, marks_per_question, option_count, section order/name, page size, or student field list changes re-run the full layout pass.
Bubble coordinates: x = col_start_x + option_index × bubble_spacing, y = section_start_y + header_height + question_index × row_spacing — same formula the PDF generator and the scanner both use.

12. Template Versioning
Version bumps only on scanner-critical geometry changes — registration marks, bubble coordinates, QR position, page size.
Color, logo, school name, header text — cosmetic, no version bump needed.
Old versions never overwritten; printed sheets stay scannable.

13. Scanner Mapping & RICOH IM 2700 Ingestion
RICOH IM 2700 → batch scan (200–300 DPI, grayscale) → detect template via QR → orientation + perspective correction (4 registration marks) → warp to canonical A4 space → load template config by template_id + version → sample bubble fill at the same x/y formula used for generation → fill-ratio threshold → answer payload → marking engine
The scanner reads bubble fill in grayscale regardless of the brand colors on the printed page — color only exists in the banner/section-bar regions the recognition engine never samples.

14. Marking Engine

{"correct": 1, "wrong_group_size": 3, "wrong_group_penalty": 1, "unanswered": 0}

Every 3 wrong = -1, applied by the evaluation engine, never printed on the sheet.

15. Dashboard Model & Validation Rules
Rule | Blocks PDF generation?
Σ(question marks in section) ≠ section allocated_marks | Yes — hard error
Σ(section allocated_marks) ≠ exam total_marks | Yes — hard error
question_count = 0 in an active section | Yes
option_count < 2 | Yes
Registration/QR/bubble/logo regions overlap | Yes — hard error
Content exceeds printable margin or quiet zone | Yes — hard error
Section reordering | No — triggers reflow + review warning
Duplicate section_id or question_no overlap | Yes — hard error

16. Print & Scanner Specification
A4 portrait, vector PDF, 100% scale, no auto-fit.
Brand colors (blue banner, orange accents) print in full color; everything the scanner samples (bubbles, registration marks, question numbers) stays pure black on white.
RICOH IM 2700: 200–300 DPI, grayscale ADF — color banner converts cleanly to grayscale for the scan pass since it never overlaps a sampled region.
